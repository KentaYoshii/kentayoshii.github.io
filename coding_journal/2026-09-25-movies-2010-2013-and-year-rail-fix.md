## Bug: year jump-rail vanishing

- `docs/assets/js/main.js` `buildRail()` falls back from full section names to
  single-character "initials" once there are more sections than
  `RAIL_MAX_NAMES` (12) — a rule written for author/series lists, where an
  initial is still a useful bucket.
- Year labels are 4-digit numbers. `foldForSearch(name).charAt(0)` on "2016"
  etc. isn't an A-Z letter, so every year collapses to a single `#` bucket.
  With only one deduplicated chip left, `chips.length < 2` hides the rail
  entirely.
- The Movies page crossed the 12-section threshold when 2014/2015 were added
  in the prior session (Undated + 13 years = 14 sections), which is when this
  broke.
- Fix: `buildRail()` now always uses full names when `mode === 'year'`,
  regardless of section count (`docs/assets/js/main.js:348`). `.jump-rail` is
  `flex-wrap: wrap`, so an arbitrarily long row of year chips still lays out
  fine. Author/series/letter groupings keep the old initials fallback.
- No JS test harness in this repo (Python/pytest only covers the build
  scripts) and no Ruby/Jekyll available in this environment to run the site
  itself. Verified by copying the exact `buildRail()` chip-building logic
  (both old and fixed) into a standalone Node script and running it against
  the 18 real section labels (Undated + 2010-2026): the old logic collapsed
  to 2 useless chips (`U`, `#`, the latter always jumping to the earliest
  year); the fix produces one chip per label, 18 total. Not a substitute for
  loading the page in a browser.
